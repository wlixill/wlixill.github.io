## 一个看起来能跑通的错误

实时分割出来之后，下一步是拿 mask 去筛点云，做 ROI。最直观的写法是：

```cpp
for (u, v) in mask.nonzero():
    d = depth(u, v)
    cloud.push_back(backproject(u, v, d))
```

在这张 mask 上，框看起来是对的，点云看起来也「有东西」。但和 CAD 模板对齐的时候，偏差总是差一点——不是差在配准参数上，而是整片点云都往一个方向平移了。

## 原因

mask 是 **RGB 图坐标**下的像素，深度图的采样格点属于 **深度相机图像坐标**。除非做过深度到 RGB 的对齐，否则同一个 `(u, v)` 在两张图上通常**不是同一个物理点**。

这两颗相机之间有外参（旋转 + 平移），基线还有几十毫米。直接用同一对像素坐标，可能取错位置；但误差怎么随距离变化，要先说清楚在量什么。

例如，两相机已校正到相同朝向、内参相同，而且只有水平基线 `B` 时，同一空间点的水平像素视差大小为 `f_x |B| / Z`。`f_x = 600 px`、`B = 0.05 m` 时，`Z = 1 m` 对应 30 px，`Z = 2 m` 对应 15 px：在这个理想模型里，近处的像素错位反而更大。

这说的是像素视差，不等于所有三维误差。例如在针孔模型里，同一深度上的固定水平像素偏差 `Δu` 对应横向距离偏差 `Z·|Δu|/f_x`，会随距离增大；旋转、深度误差和遮挡也会影响结果。不能把「近小远大」当作不带条件的规律。

## 正确方向：把深度点投影到 RGB 图，再查 mask

不生成对齐深度图，也可以逐点做几何映射。下面按常见针孔模型说明：两张图已去畸变，内参匹配各自图像的尺寸与裁剪，`R`、`t` 是从深度相机系到 RGB 相机系的外参，mask 也处在对应的 RGB 图坐标系。深度 `Z_d` 是沿深度相机光轴的 **Z 轴深度**，不是相机到点的欧氏距离。

```text
遍历未对齐、已去畸变的 depth 像素 (u_d, v_d)
  -> 读取并换算深度，得到与 t 单位一致的 Z_d；无效或 Z_d <= 0 则跳过
  -> 用深度内参反投影：P_d = Z_d * K_d^-1 * [u_d, v_d, 1]^T
  -> 变换到 RGB 相机系：P_rgb = R * P_d + t；若 P_rgb.z <= 0 则跳过
  -> 用 RGB 内参投影：q = K_rgb * P_rgb
  -> 透视除法：(u_r, v_r) = (q.x / q.z, q.y / q.z)
  -> 按 mask 的像素采样约定取样，越界则跳过
  -> 如果对应像素属于该 detection 的 mask，就把 P_rgb 收进 ROI 点云
```

如果设备输出的是沿视线的欧氏距离 `range`，要先将 `K_d^-1 [u_d, v_d, 1]^T` 得到的射线归一化，再乘 `range`，不能把它直接当成 `Z_d`。

拿上面的理想参数举个算例：两张图的 `f_x = f_y = 600 px`、`(c_x, c_y) = (320, 240)`，`R = I`、`t = (0.05, 0, 0) m`。深度像素 `(350, 252)` 的 `Z_d = 2 m`，反投影得到 `P_d = (0.10, 0.04, 2) m`；变换得到 `P_rgb = (0.15, 0.04, 2) m`；透视除法后 `(u_r, v_r) = (365, 252)`。这里相差 15 px，和前面的理想视差算例一致；它只是算数例子，不是这次的实测。

这样做的好处是：

- 不需要调用 `AlignDepthToRGB()`，避免生成一张重采样后的对齐深度图；
- 选入的点在 **RGB 相机系**下，只要后续位姿也在该系，就可以直接比较；
- mask 本身就是像素级 ROI，不一定需要再套一层 `cropROI(center, size)` 的盒子裁剪；如果后续还要按空间范围筛选，则另当别论。

几何投影也不是万能的：遮挡、视场差、深度空洞、像素取整和时间不同步都可能造成错配。多个深度点落到同一 RGB 像素时，可以按 `Z_rgb` 用 z-buffer 保留最近点，但深度相机没看到的遮挡面不能凭这一操作补出来。原始图若未去畸变，反投影和投影还需要结合各自的畸变模型。

## 顺手记下的两条

**坐标系要一次说清。** 一个点从深度反投影出来是「深度相机系」，变到 RGB 系之后才是「RGB 相机系」，最后输出给业务的位姿又是哪个系？这三者只要中间混了一次，后面调参全是白费。

**单位也要说清。** 先按设备约定把原始深度换算成米或毫米，再确保外参平移 `t` 使用相同的长度单位；旋转 `R` 本身没有长度单位。常见针孔内参里的 `f_x`、`f_y`、`c_x`、`c_y` 用像素表示，不应随三维长度单位换算。差 1000 倍的错误不会报错：既可能让点云尺寸不对，也可能让平移量相对深度失真。

如果只留一句话：**在拿像素坐标做任何事之前，先问它属于哪张图。**
